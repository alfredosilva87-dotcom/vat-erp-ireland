Which installation is this?

There are two shapes. Pick the wrong one and the data ends up in the wrong place, so read this table first.

Per-PCPractice server this manual
Who uses itOne person, one machineSeveral people, the same data
DatabaseOne per PC, not sharedOne, central
The stationsEach installs everythingOnly open a browser
Installerinstall.command / install.batinstall-server.bat
Several people with the same data? Then it is the server. Two per-PC installs do not sync — each would keep its own separate books, and nobody would notice until the two disagreed.

Before you start

The machine

MinimumRecommended
RAM8 GB16 GB
Free disk20 GB60 GB (invoice files grow)
SystemWindows 10/11 64-bit, or Linux—
NetworkFixed IP or reserved DHCPA name on the local DNS

It should be a machine that stays on. If it sleeps, the system is unreachable while it sleeps.

This machine's own address on the office network is what every station types to reach it — and, if sending from a phone is turned on later, it is also what the link sent by WhatsApp ultimately leads back to. If the router hands out addresses freely, which is the default, the machine can be given a different one after the next reboot, and every bookmark and every phone link silently stops working. Ask whoever manages the office network for a DHCP reservation for this machine, or set a static address by hand — either way, write the address down: it is what you type as the server's address during install.

Ports 80 and 443 must be free on this machine. They are what lets HTTPS work without anyone typing a port number. Something else already using them — IIS, Skype for Business, another web server — makes the installer stop with “port already in use.” Free them for this app, or reserve different ones by setting VATERP_HTTPS_PORT (and VATERP_HTTP_PORT) before running the installer — PowerShell example: $env:VATERP_HTTPS_PORT="3010".

Two programs, in this order

  1. Node.js — the LTS version, from nodejs.org.
  2. Docker Desktop — from docs.docker.com/desktop.
    On Windows it needs WSL2. If Docker opens saying “WSL is not installed”, open PowerShell as administrator, run wsl --install, restart, then open Docker again.
macOS 13 (Ventura) or older cannot run Docker Desktop. Use Colima instead — the installer works with either, because it only needs a working docker command.

Getting the files

The repository is private, so downloading needs an account with access.

  1. With Git (recommended, because updating is then one command):
    git clone https://github.com/alfredosilva87-dotcom/vat-erp-ireland.git
    Git asks for your GitHub user and a personal access token as the password.
  2. Without Git: on the repository page, Code → Download ZIP, then unzip it into a folder with no spaces in the path — for example C:\vat-erp.

Installing

  1. Open Docker and wait until it says it is running. The installer fails early and clearly if Docker is not up, but waiting saves you the round trip.
  2. Run the installer from the selfhost folder:
    Windows: double-click install-server.bat
    Mac/Linux: node selfhost/scripts/install-server.js
  3. Answer three questions: the administrator e-mail, the administrator password, and the Gemini API key (free, from aistudio.google.com → Get API key).
  4. Wait. It picks free ports, generates the keys, brings up the database, applies the schema files, creates the administrator and builds the application. First run takes several minutes because Docker is downloading images.
  5. Write down the address it prints at the end — something like https://192.168.0.20:3010. That is what the stations open.
The database is born empty of client data. Structure, the Irish VAT rate base, the credit rules and one administrator. No client's real data is copied in — that comes from your own imports.

HTTPS, and why it is not optional

Sign-in uses a session cookie marked Secure, which browsers only store over HTTPS. Over plain http:// on an IP address, sign-in appears to work, the cookie is silently dropped, and the screen bounces back to the login page.

The server installer generates a certificate and serves HTTPS for exactly this reason. Because the certificate is issued by the server's own authority, each station has to trust that authority once:

  1. Chrome / Edge: Advanced → Proceed.
  2. Firefox: Advanced → Accept the risk and continue.
  3. To remove the warning for good, install the CA on each station — node selfhost/scripts/export-ca.js writes selfhost/server/root-ca.crt, the file to import. Windows, as administrator:
    Import-Certificate -FilePath .\root-ca.crt -CertStoreLocation Cert:\LocalMachine\Root
    Firefox keeps its own store: Settings → Certificates → View certificates → Authorities → Import.
Still says “not secure” when you browse by IP? Trusting the CA fixes “unknown authority”. It cannot fix “wrong name”: a certificate issued for the machine's name does not match the IP address you typed, and the browser compares what you typed. From v1.31 the installer puts the machine's LAN addresses inside the certificate, so both the name and the IP are accepted — on a server installed before that, run the installer again to reissue.

Backups — the part everyone skips

backup writes the database and the invoice files to a dated folder. Copy that folder somewhere off the machine — a backup that lives only on the machine it is protecting is not a backup. Test a restore once, before you need it.

Updating

  1. Back up first. Always.
  2. git pull (or download the new ZIP over the folder).
  3. Run the installer again. It is idempotent: schema files that already ran do nothing, new ones are applied. Existing data is not touched.
  4. start again.

Email intake (optional)

To let invoices arrive by e-mail, add these to .env.local and restart. The server fetches by IMAP — it never receives SMTP, so no port has to be opened.

VariableWhat it is
MAIL_IMAP_HOSTimap.gmail.com, outlook.office365.com, …
MAIL_IMAP_PORT993
MAIL_IMAP_USERThe practice's mailbox
MAIL_IMAP_PASSWORDAn app password — Gmail and Microsoft 365 refuse the account password
MAIL_INBOX_ADDRESSThe base address, so the app can show notes+token@… per client
The password lives in the environment, never in the database. A database dump must not carry the practice's e-mail password along with the invoices.

Sending from a phone (optional)

A client photographs a receipt where it is handed to them — at the pump, at the counter — adjusts the four corners if the photo came out crooked, and it arrives in the Inbox on its own, the same way an e-mailed invoice does.

The phone is on the mobile network; this server sits on the office's own local network and is not reachable from outside it — that is the whole point of a self-hosted install. So the photo cannot go straight to this machine. It goes first to a small, separate piece in the cloud — a relay — which holds it only until this server fetches it, then deletes it. The relay never holds anything else: no invoice, no figure, no client list.

The relay must be a project of its own — not the one used to demonstrate the system to a client, and not this office's own database. It carries real photographs of real receipts in transit, even if only for a few minutes.

1. Create the relay

  1. Go to supabase.com and sign in, or create a free account.
  2. New project. A recognisable name, such as vat-erp-passagem. A region close to the practice — Ireland (eu-west-1), if offered. Wait a minute or two for it to finish setting up.
  3. Open SQL Editor in the left sidebar, then New query. In the downloaded files, open selfhost/schema/relay/001_relay.sql, copy all of it, paste it in, and press Run. This creates the two tables the relay needs and locks them so nobody but this server can read what is inside.
  4. Open Settings → API Keys. Two values on this page are needed shortly: the Project URL, and the secret key (press Reveal to see it — it starts with sb_secret_). Leave this tab open.

2. Publish the phone screen

  1. Go to vercel.com and sign in with the GitHub account that has access to the repository.
  2. Add New → Project, and import the same repository again — Vercel warns it is already used elsewhere; that is expected, continue. Name this project something like vat-erp-captura.
  3. Before deploying, open Environment Variables and add these six, for Production, Preview and Development:
    VariableValue
    RELAY_SUPABASE_URLThe Project URL, from step 1
    RELAY_SUPABASE_SERVICE_ROLE_KEYThe secret key, from step 1
    NEXT_PUBLIC_SUPABASE_URLThe same Project URL, again
    NEXT_PUBLIC_SUPABASE_ANON_KEYThe publishable key — same API Keys page, not the secret one
    SUPABASE_SERVICE_ROLE_KEYThe same secret key, once more
    AUTH_SECRETA new random value — see below
    RELAY_ONLY1
  4. To generate AUTH_SECRET: Mac/Linux, openssl rand -base64 32. Windows PowerShell:
    [Convert]::ToBase64String((1..32|%{Get-Random -Max 256}))
  5. Deploy. When it finishes, note the address Vercel gives it — something like https://vat-erp-captura.vercel.app.
RELAY_ONLY is what keeps this publication safe. With it set, this deployment serves nothing except the phone-capture screen — sign-in and every other part of the system answer “not found”. Skipping it does not let anyone in on its own (the relay's database has no user accounts to sign in as), but it needlessly leaves the shape of the system visible on the internet.

3. Tell this server about the relay

  1. Open selfhost/docker/.env in a plain text editor and add three lines at the end:
    RELAY_SUPABASE_URL=the same Project URL
    RELAY_SUPABASE_SERVICE_ROLE_KEY=the same secret key
    PHONE_CAPTURE_URL=the address Vercel gave the capture site
  2. Restart the app: docker compose up -d app, from the selfhost/docker folder.

4. Use it

Open a client, tab Details, section Send from a phone. Type who the link is for, create it, copy it, and send it once — WhatsApp is the obvious way. That person adds it to their phone's home screen; from then on it opens straight to the camera. Revoke a link and issue a new one if a phone is lost — nothing else is needed.

The licence

The licence key arrives by e-mail and is activated by the practice's own administrator — nobody has to sign in to this installation to issue or renew it.

  1. Open Settings → Licence. It shows what you have: the company it was issued for, the date it runs to, and how many days are left.
  2. Paste the key you were sent (it starts with VATERP1.) and press Activate.
  3. The system checks the signature on the spot. No internet connection is needed.

A key issued for another company, one that has expired, or one that would shorten the current licence is refused, and nothing changes. Pasting the same key twice is harmless.

Baixar os arquivos

O repositório é privado, então baixar exige uma conta com acesso.

  1. Com Git (recomendado, porque atualizar depois é um comando):
    git clone https://github.com/alfredosilva87-dotcom/vat-erp-ireland.git
    O Git pede o usuário do GitHub e um token de acesso pessoal como senha.
  2. Sem Git: na página do repositório, Code → Download ZIP, e descompacte numa pasta sem espaços no caminho — por exemplo C:\vat-erp.

Instalar

  1. Abra o Docker e espere ele dizer que está rodando. O instalador para cedo e com mensagem clara se o Docker não estiver de pé, mas esperar poupa a ida e volta.
  2. Rode o instalador, na pasta selfhost:
    Windows: dois cliques em install-server.bat
    Mac/Linux: node selfhost/scripts/install-server.js
  3. Responda três perguntas: e-mail do administrador, senha do administrador, e a chave da API do Gemini (grátis, em aistudio.google.com → Get API key).

O banco nasce sem dado de cliente. Estrutura, a base de alíquotas irlandesas, as regras de crédito e um administrador. Nenhum dado real de cliente é copiado — isso vem das suas próprias importações.

HTTPS, e por que não é opcional

O login usa um cookie de sessão marcado como Secure, que os navegadores só guardam sobre HTTPS. Em http:// puro num IP, o login parece funcionar, o cookie é descartado em silêncio, e a tela volta para o login.

O instalador de servidor gera um certificado e serve HTTPS exatamente por isso. Como o certificado é emitido pela autoridade do próprio servidor, cada estação precisa confiar nessa autoridade uma vez:

  1. Chrome / Edge: Avançado → Prosseguir.
  2. Firefox: Avançado → Aceitar o risco e continuar.
  3. Para tirar o aviso de vez, instale a CA em cada estação — node selfhost/scripts/export-ca.js grava selfhost/server/root-ca.crt, o arquivo a importar. No Windows, como administrador:
    Import-Certificate -FilePath .\root-ca.crt -CertStoreLocation Cert:\LocalMachine\Root
    O Firefox tem armazenamento próprio: Configurações → Certificados → Ver certificados → Autoridades → Importar.
Continua dizendo “não seguro” quando você acessa pelo IP? Confiar na CA resolve “autoridade desconhecida”. Não resolve “nome errado”: um certificado emitido para o nome da máquina não casa com o endereço IP que você digitou, e o navegador compara o que foi digitado. A partir da v1.31 o instalador põe os endereços de rede da máquina dentro do certificado, então nome e IP passam os dois — em servidor instalado antes disso, rode o instalador de novo para reemitir.

Enviar pelo telefone (opcional)

O cliente fotografa a nota onde ela é entregue a ele — no posto, no balcão — ajusta os 4 cantos se a foto saiu torta, e ela chega sozinha na Caixa de entrada, do mesmo jeito que uma nota por e-mail.

O telefone está na rede móvel; este servidor fica na rede local do escritório e não é alcançável de fora dela — é esse o ponto inteiro de uma instalação self-hosted. Então a foto não pode ir direto para esta máquina. Ela vai primeiro para uma peça pequena e separada na nuvem — uma passagem — que guarda a foto só até este servidor buscar, e então apaga. A passagem nunca guarda mais nada: nem nota, nem valor, nem lista de clientes.

A passagem precisa ser um projeto próprio — não o mesmo usado para apresentar o sistema a um cliente, e não o banco deste próprio escritório. Ela carrega fotos de notas de verdade em trânsito, mesmo que só por alguns minutos.

1. Criar a passagem

  1. Vá em supabase.com e entre, ou crie uma conta grátis.
  2. New project. Um nome reconhecível, como vat-erp-passagem. Uma região perto do escritório — Ireland (eu-west-1), se for oferecida. Espere um ou dois minutos até terminar de configurar.
  3. Abra SQL Editor na barra lateral, depois New query. Nos arquivos baixados, abra selfhost/schema/relay/001_relay.sql, copie tudo, cole ali, e clique em Run. Isso cria as duas tabelas que a passagem precisa e as tranca, para que ninguém além deste servidor consiga ler o que está dentro.
  4. Abra Settings → API Keys. Dois valores desta página vão ser precisos logo — a Project URL, e a chave secret (clique em Reveal para ver — começa com sb_secret_). Deixe esta aba aberta.

2. Publicar a tela de captura

  1. Vá em vercel.com e entre com a conta do GitHub que tem acesso ao repositório.
  2. Add New → Project, e importe o mesmo repositório de novo — a Vercel avisa que ele já está em uso em outro lugar; é esperado, continue. Dê um nome a este projeto como vat-erp-captura.
  3. Antes de publicar, abra Environment Variables e acrescente estas seis, marcando Production, Preview e Development:
    VariávelValor
    RELAY_SUPABASE_URLA Project URL, do passo 1
    RELAY_SUPABASE_SERVICE_ROLE_KEYA chave secret, do passo 1
    NEXT_PUBLIC_SUPABASE_URLA mesma Project URL, de novo
    NEXT_PUBLIC_SUPABASE_ANON_KEYA chave publishable — mesma página de API Keys, não a secret
    SUPABASE_SERVICE_ROLE_KEYA mesma chave secret, mais uma vez
    AUTH_SECRETUm valor aleatório novo — veja abaixo
    RELAY_ONLY1
  4. Para gerar o AUTH_SECRET: Mac/Linux, openssl rand -base64 32. PowerShell no Windows:
    [Convert]::ToBase64String((1..32|%{Get-Random -Max 256}))
  5. Publique. Quando terminar, anote o endereço que a Vercel deu — algo como https://vat-erp-captura.vercel.app.
RELAY_ONLY é o que mantém essa publicação segura. Com ela ligada, essa implantação não serve nada além da tela de captura — o login e todo o resto do sistema respondem "não encontrado". Sem ela, ninguém entra mesmo assim (o banco da passagem não tem conta de usuário nenhuma), mas o formato do sistema fica visível na internet à toa.

3. Avisar este servidor sobre a passagem

  1. Abra selfhost/docker/.env num editor de texto simples e acrescente três linhas no fim:
    RELAY_SUPABASE_URL=a mesma Project URL
    RELAY_SUPABASE_SERVICE_ROLE_KEY=a mesma chave secret
    PHONE_CAPTURE_URL=o endereço que a Vercel deu à tela de captura
  2. Reinicie o aplicativo: docker compose up -d app, de dentro da pasta selfhost/docker.

4. Usar

Abra um cliente, aba Cadastro, seção Enviar pelo telefone. Diga de quem é o link, crie, copie, e mande uma vez — WhatsApp é o jeito óbvio. Essa pessoa adiciona à tela inicial do telefone dela; a partir daí abre direto na câmera. Revogue um link e emita um novo se um telefone se perder — não precisa de mais nada.

A licença

A chave de licença chega por e-mail e é ativada pelo próprio administrador do escritório — ninguém precisa entrar nesta instalação para emitir ou renovar.

  1. Abra Configurações → Licença. Ela mostra o que você tem: para quem foi emitida, até quando vale, e quantos dias faltam.
  2. Cole a chave que você recebeu (começa com VATERP1.) e clique em Ativar.
  3. O sistema confere a assinatura na hora. Não precisa de internet.

Chave emitida para outra empresa, chave vencida, ou chave que encurtaria a licença atual é recusada, e nada muda. Colar a mesma chave duas vezes é inofensivo.
