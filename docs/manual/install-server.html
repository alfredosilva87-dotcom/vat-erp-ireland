Which installation is this?

There are two shapes. Pick the wrong one and the data ends up in the wrong place, so read this table first.

Per-PCPractice server this manual

Several people with the same data? Then it is the server. Two per-PC installs do not sync — each would keep its own separate books, and nobody would notice until the two disagreed.

Before you start

The machine

MinimumRecommended
RAM8 GB16 GB
Free disk20 GB60 GB (invoice files grow)
SystemWindows 10/11 64-bit, or Linux—
NetworkFixed IP or reserved DHCPA name on the local DNS

It should be a machine that stays on. If it sleeps, the system is unreachable while it sleeps.

Two programs, in this order

  1. Node.js — the LTS version, from nodejs.org.
  2. Docker Desktop — from docs.docker.com/desktop.
    On Windows it needs WSL2. If Docker opens saying “WSL is not installed”, open PowerShell as administrator, run wsl --install, restart, then open Docker again.
macOS 13 (Ventura) or older cannot run Docker Desktop. Use Colima instead — the installer works with either, because it only needs a working docker command.

Getting the files

The repository is private, so downloading needs an account with access.

  1. With Git (recommended, because updating is then one command):
    git clone https://github.com/alfredosilva87-dotcom/vat-erp-ireland.git
    Git asks for your GitHub user and a personal access token as the password.
  2. Without Git: on the repository page, Code → Download ZIP, then unzip it into a folder with no spaces in the path — for example C:\vat-erp.

Installing

  1. Open Docker and wait until it says it is running. The installer fails early and clearly if Docker is not up, but waiting saves you the round trip.
  2. Run the installer from the selfhost folder:
    Windows: double-click install-server.bat
    Mac/Linux: node selfhost/scripts/install-server.js
  3. Answer three questions: the administrator e-mail, the administrator password, and the Gemini API key (free, from aistudio.google.com → Get API key).
  4. Wait. It picks free ports, generates the keys, brings up the database, applies the nine schema files, creates the administrator and builds the application. First run takes several minutes because Docker is downloading images.
  5. Write down the address it prints at the end — something like https://192.168.0.20:3010. That is what the stations open.
The database is born empty of client data. Structure, the Irish VAT rate base, the credit rules and one administrator. No client's real data is copied in — that comes from your own imports.

HTTPS, and why it is not optional

Sign-in uses a session cookie marked Secure, which browsers only store over HTTPS. Over plain http:// on an IP address, sign-in appears to work, the cookie is silently dropped, and the screen bounces back to the login page.

The server installer generates a certificate and serves HTTPS for exactly this reason. Because the certificate is self-signed, each station shows a warning the first time:

  1. Chrome / Edge: Advanced → Proceed.
  2. Firefox: Advanced → Accept the risk and continue.
  3. To remove the warning for good, install the CA on each station — node selfhost/scripts/export-ca.js writes out the file to import.

Set the machine to run start at boot, so a power cut does not leave the practice without the system until somebody notices.

Backups — the part everyone skips

backup writes the database and the invoice files to a dated folder. Copy that folder somewhere off the machine — a backup that lives only on the machine it is protecting is not a backup. Test a restore once, before you need it.

Updating

  1. Back up first. Always.
  2. git pull (or download the new ZIP over the folder).
  3. Run the installer again. It is idempotent: schema files that already ran do nothing, new ones are applied. Existing data is not touched.
  4. start again.

Email intake (optional)

To let invoices arrive by e-mail, add these to .env.local and restart. The server fetches by IMAP — it never receives SMTP, so no port has to be opened.

VariableWhat it is
MAIL_IMAP_HOSTimap.gmail.com, outlook.office365.com, …
MAIL_IMAP_PORT993
MAIL_IMAP_USERThe practice's mailbox
MAIL_IMAP_PASSWORDAn app password — Gmail and Microsoft 365 refuse the account password
MAIL_INBOX_ADDRESSThe base address, so the app can show notes+token@… per client
The password lives in the environment, never in the database. A database dump must not carry the practice's e-mail password along with the invoices.

When it does not work

SymptomCause and fix
Installer stops on DockerDocker is not running, or WSL2 is missing on Windows. Open Docker, wait for “running”, try again.
Sign-in loops back to the login pageYou are on http://. Use the https:// address the installer printed.
A station cannot reach the serverWindows Firewall on the server. Allow inbound TCP on the port the installer chose.
“Port already in use”Another program has it. The installer picks free ports; if you fixed one by hand, free it or change it.
Everything was working, then stoppedThe machine restarted and start did not run. Check the logs and set it to start at boot.

Baixar os arquivos

O repositório é privado, então baixar exige uma conta com acesso.

  1. Com Git (recomendado, porque atualizar depois é um comando):
    git clone https://github.com/alfredosilva87-dotcom/vat-erp-ireland.git
    O Git pede o usuário do GitHub e um token de acesso pessoal como senha.
  2. Sem Git: na página do repositório, Code → Download ZIP, e descompacte numa pasta sem espaços no caminho — por exemplo C:\vat-erp.

Instalar

  1. Abra o Docker e espere ele dizer que está rodando. O instalador para cedo e com mensagem clara se o Docker não estiver de pé, mas esperar poupa a ida e volta.
  2. Rode o instalador, na pasta selfhost:
    Windows: dois cliques em install-server.bat
    Mac/Linux: node selfhost/scripts/install-server.js
  3. Responda três perguntas: e-mail do administrador, senha do administrador, e a chave da API do Gemini (grátis, em aistudio.google.com → Get API key).
  4. Espere. Ele escolhe portas livres, gera as chaves, sobe o banco, aplica os nove arquivos de schema, cria o administrador e compila a aplicação. A primeira vez leva vários minutos porque o Docker está baixando imagens.
  5. Anote o endereço que ele imprime no fim — algo como https://192.168.0.20:3010. É o que as estações abrem.
O banco nasce sem dado de cliente. Estrutura, a base de alíquotas irlandesas, as regras de crédito e um administrador. Nenhum dado real de cliente é copiado — isso vem das suas próprias importações.

HTTPS, e por que não é opcional

O login usa um cookie de sessão marcado como Secure, que os navegadores só guardam sobre HTTPS. Em http:// puro num IP, o login parece funcionar, o cookie é descartado em silêncio, e a tela volta para o login.

O instalador de servidor gera um certificado e serve HTTPS exatamente por isso. Como o certificado é autoassinado, cada estação mostra um aviso na primeira vez:

  1. Chrome / Edge: Avançado → Prosseguir.
  2. Firefox: Avançado → Aceitar o risco e continuar.
  3. Para tirar o aviso de vez, instale a CA em cada estação — node selfhost/scripts/export-ca.js gera o arquivo a importar.

Backup — a parte que todos pulam

O backup grava o banco e os arquivos das notas numa pasta com data. Copie essa pasta para fora da máquina — backup que mora só na máquina que ele protege não é backup. Teste uma restauração uma vez, antes de precisar.

Atualizar

  1. Backup primeiro. Sempre.
  2. git pull (ou baixe o ZIP novo por cima da pasta).
  3. Rode o instalador de novo. Ele é idempotente: arquivo de schema que já rodou não faz nada, e os novos são aplicados. Dado existente não é tocado.
  4. start de novo.

Para as notas chegarem por e-mail, acrescente isto ao .env.local e reinicie. O servidor busca por IMAP — ele nunca recebe SMTP, então nenhuma porta precisa ser aberta.
