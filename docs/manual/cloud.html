What this version is for

Trying the system out, showing it to someone, and finding out what still needs improving — without installing anything.

Read this before putting anything real in. In the cloud version the data sits on managed infrastructure outside the practice. The whole reason the server version exists is the Irish data-protection requirement that the practice's data stays in the practice. Use the cloud version for demonstration and testing; keep real client books on the server version.

Getting in

  1. Open the address the practice gave you.
  2. Sign in with your e-mail and password. First sign-in asks you to change the password.
  3. Set the language and the theme at the foot of the left sidebar.

From here on, everything works exactly as in the user manual — same screens, same buttons, same order of work.

A sensible way to test it

Half an hour, in this order, gives you an opinion about the whole system rather than one screen.

  1. Create a fake client. Give it a chart of accounts with four or five accounts.
  2. Drag in five real invoices from different suppliers — including one supermarket receipt with many lines, which is the hardest case.
  3. Correct one line on purpose. Then open the invoice's History and check it recorded who, what and when.
  4. Write a supplier rule for a recurring supplier, with line items switched off. Import an invoice from them again and watch it come in as a single line.
  5. Import a bank statement — the real file from your bank, whatever shape it is in. This is the step that teaches the most.
  6. Reconcile a payment against one of the invoices, and check the invoice becomes paid.
  7. Close the month, typing in the closing balance from the paper statement. If the difference is not zero, some bank line never got imported — that is the check earning its keep.
  8. Approve everything in bulk from the Database screen.
What to send back. Any file the reader got wrong — a bank statement in a shape it misread, an invoice whose totals came out wrong. Those are worth more than a list of opinions: the first real AIB statement corrected two wrong assumptions in the PDF reader, and the first real mail server corrected the duplicate key in the inbox queue.

Limits worth knowing

  • Reading is the slow part. Roughly twenty seconds per document, eight at a time — a batch of fifty lands around three minutes. Saving is fast.
  • Reading uses an AI quota. On the free tier a very large batch can hit the limit; it retries and reports rather than failing silently.
  • Test data is test data. Anything you enter here should be disposable.

Moving to the server version

When testing is done and it goes into real use, follow the server installation manual. The cloud data does not migrate automatically, and that is deliberate: the server database is meant to be born clean, with structure, the VAT rate base and one administrator — never with somebody's test invoices inside.

Um jeito sensato de testar

Meia hora, nesta ordem, dá uma opinião sobre o sistema inteiro em vez de sobre uma tela.

  1. Crie um cliente fictício. Dê a ele um plano de contas com quatro ou cinco contas.
  2. Arraste cinco notas de verdade de fornecedores diferentes — incluindo um recibo de supermercado com muitas linhas, que é o caso mais difícil.
  3. Corrija uma linha de propósito. Depois abra o Histórico da nota e confira que ficou registrado quem, o quê e quando.
  4. Escreva uma regra de fornecedor para um fornecedor recorrente, com os itens de linha desligados. Importe outra nota dele e veja entrar como uma linha só.
  5. Importe um extrato bancário — o arquivo real do seu banco, na forma que ele vier. É o passo que mais ensina.
  6. Concilie um pagamento com uma das notas, e confira que a nota vira paga.
  7. Feche o mês, digitando o saldo final do extrato de papel. Se a diferença não for zero, alguma linha do banco nunca foi importada — é a conferência fazendo o que ela existe para fazer.
  8. Aprove tudo em lote na tela da Base de dados.
O que vale mandar de volta. Qualquer arquivo que o leitor errou — um extrato numa forma que ele leu torto, uma nota cujos totais saíram errados. Vale mais que uma lista de opiniões: o primeiro extrato real do AIB corrigiu duas suposições erradas do leitor de PDF, e o primeiro servidor de e-mail real corrigiu a chave de duplicata da fila.

Limites que vale conhecer

  • A leitura é a parte lenta. Cerca de vinte segundos por documento, oito ao mesmo tempo — um lote de cinquenta fica em torno de três minutos. Gravar é rápido.
  • A leitura consome cota de IA. No plano gratuito um lote muito grande pode bater no limite; ele tenta de novo e relata, em vez de falhar em silêncio.
  • Dado de teste é dado de teste. Tudo o que você lançar aqui deve ser descartável.

Passar para a versão servidor

Quando o teste terminar e for para uso real, siga o manual de instalação no servidor. O dado da nuvem não migra automaticamente, e isso é de propósito: o banco do servidor nasce limpo, com estrutura, a base de alíquotas e um administrador — nunca com as notas de teste de alguém dentro.
